---
title: Self-hosting
description: Run your own Revive ST server so your speakers don't depend on ours.
---

By default, the app and your speakers use the Revive ST server at `api.revivest.app`: it stores your presets, and your speakers ask it for their account, presets and stations every time they start. You can run that server yourself, on a computer at home, so your speakers keep working whatever happens to ours.

## What you need

- **A computer that's always on** when your speakers are, with [Docker](https://docs.docker.com/get-docker/): a NAS, a home server or a Raspberry Pi (64-bit OS). The server image runs on `amd64` and `arm64`.
- **A fixed address for it on your network**, such as `192.168.1.10`. Most routers can reserve an address for a device ("DHCP reservation").
- **Internet access for the server**: TuneIn stations are looked up through TuneIn when they play.
- **The Revive ST app** on a phone on the same network.

## Run the server

With Docker Compose, download the [compose file](https://github.com/pradel/revive-st/blob/main/apps/api/compose.yaml) and start it:

```bash
curl -O https://raw.githubusercontent.com/pradel/revive-st/main/apps/api/compose.yaml
docker compose up -d
```

Or with Docker alone:

```bash
docker run -d --name revive-st --restart unless-stopped \
  -p 3000:3000 -v revive-st-data:/data \
  ghcr.io/pradel/revive-st-api:latest
```

To check it's running, open `http://192.168.1.10:3000` (with your server's address) in your phone's browser: it shows `Revive ST API` and the version it runs.

Your accounts and presets are stored in the `/data` volume, in the SQLite database file `revivest.db` (with `revivest.db-wal` and `revivest.db-shm` beside it while the server runs). Back up that whole volume to keep them.

| Setting              | Default             | What it does                                                                                                                                                                                                                                                                                                                             |
| -------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT`               | `3000`              | The port the server listens on inside the container.                                                                                                                                                                                                                                                                                     |
| `DATABASE_PATH`      | `/data/revivest.db` | The SQLite database file where accounts and presets are stored.                                                                                                                                                                                                                                                                          |
| `LOG_LEVEL`          | `info`              | `debug` also logs every request the server answers, not only rejected ones (4xx) and errors (5xx). `warn` and `error` log less.                                                                                                                                                                                                          |
| `LOG_FORMAT`         | `pretty`            | `json` writes one JSON object per line, for log collectors.                                                                                                                                                                                                                                                                              |
| `RATE_LIMIT`         | `true`              | `false` turns off the per-client rate limits on writes. Clients are told apart by the `X-Real-IP` header, else their connection's address. Turn the limits off behind a proxy that doesn't set `X-Real-IP`, where every client would share the proxy's limit; without a proxy, a client can name its own `X-Real-IP` and get round them. |
| `DATABASE_BUDGET_MB` | `2500`              | Past this size the server pairs no new speaker; speakers already paired keep working. SQLite refuses to grow at one and a half times it, so leave room for that on the database's disk. A backup also needs about as much again in the temporary directory while it runs.                                                                |

### Daily backups to S3 storage (optional)

The server can store a gzipped snapshot of its database in a bucket on any S3-compatible storage (Cloudflare R2, AWS S3, Backblaze B2, MinIO…) every day at 03:00 UTC, taken while it keeps serving. At start, it takes one right away if the newest snapshot is more than a day old, so a restart never costs a day. Snapshots are named `db/<date and time>.db.gz`; to keep only the last 30 days, add a lifecycle rule to the bucket. The snapshot goes through the temporary directory and up in 8 MiB parts (a multipart upload), so memory stays flat whatever the database's size; an upload that fails is aborted, and a server stopped mid-upload leaves parts that a lifecycle rule aborting incomplete multipart uploads cleans up.

| Setting                | What it does                                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `S3_BUCKET`            | The bucket. Backups are off without it.                                                                                        |
| `S3_ENDPOINT`          | The storage's S3 API address, like `https://<account id>.r2.cloudflarestorage.com` for R2. The bucket is addressed path-style. |
| `S3_REGION`            | Defaults to `auto`, which R2 expects. On AWS, the bucket's region.                                                             |
| `S3_ACCESS_KEY_ID`     | An access key allowed to read and write objects in this bucket only (on R2: an API token with **Object Read & Write** on it).  |
| `S3_SECRET_ACCESS_KEY` | That key's secret.                                                                                                             |

To restore a snapshot, stop the server, download the snapshot, unzip it (`gunzip`) into `/data/revivest.db`, delete `revivest.db-wal` and `revivest.db-shm`, and start the server.

## Point the app at your server

In the app, open **Settings** → **Network** → **Server**, enter your server's address, for example `http://192.168.1.10:3000`, and tap **Save**. The app checks that a Revive ST server answers there before switching.

Plain `http://` only works with an IP address, a `.local` name or a name without dots (like `nas`). For any other name, put the server behind a reverse proxy with HTTPS and enter its `https://` address.

## Set up your speakers

For each speaker, open its settings and tap **Set up internet radio**. A speaker set up for another server shows **Needs setup** until you do. The app saves the speaker's presets to your server, points the speaker's radio, account, statistics and software update addresses at it, and restarts the speaker. Setup finishes once the speaker has contacted your server after the restart; servers older than this check finish without it.

A speaker keeps using the server it was set up with until you set it up again, whatever server the app is set to.

## Update the server

```bash
docker compose pull
docker compose up -d
```

The server updates its database when it starts. `latest` is the newest release; to pick a version, use its number as the image tag, like `ghcr.io/pradel/revive-st-api:0.1.0`. The server's address shows the version it runs.

## Tracing (optional)

The server can send a trace of every request it handles, the database queries it runs and the calls it makes to TuneIn and Radio Browser to any [OpenTelemetry](https://opentelemetry.io/) backend that accepts OTLP over HTTP, such as [Jaeger](https://www.jaegertracing.io/) or an OpenTelemetry Collector. Tracing is off unless you set these settings:

| Setting                       | Example                    | What it does                                                                              |
| ----------------------------- | -------------------------- | ----------------------------------------------------------------------------------------- |
| `OTEL_TRACES_EXPORTER`        | `otlp`                     | Turns tracing on.                                                                         |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://192.168.1.10:4318` | Your backend's OTLP/HTTP address. The server sends traces to `/v1/traces` on it.          |
| `OTEL_SERVICE_NAME`           | `revive-st`                | The name the traces are filed under. Required when tracing is on.                         |
| `OTEL_EXPORTER_OTLP_HEADERS`  | `authorization=Bearer abc` | Optional headers for backends that need a key, as `name=value` pairs separated by commas. |

Traces are sent as protobuf over HTTP, usually on port `4318`; OTLP over gRPC isn't supported. With Docker Compose, add the settings under `environment:` in the compose file, then run `docker compose up -d`.

Traces include the paths of the requests your speakers make, and those paths contain your household's account id. Only send them to a backend you trust.

## Go back to the Revive ST server

In **Settings** → **Network** → **Server**, tap **Use the Revive ST server**, then configure each speaker again.

## Good to know

- **Keep the server running.** Speakers fetch their account and presets from it every time they start, and TuneIn and Radio Browser stations play through it. A speaker that starts while the server is down keeps its presets, but can't play those stations until the server is back.
- **Keep the server on your home network.** Anyone who can reach it and knows your household's account id can read and change your presets, and the account id travels unencrypted on your network. If the computer is also reachable from the internet, publish the port on its home-network address only, for example `"192.168.1.10:3000:3000"` in the compose file, or block it with a firewall.
- On **iOS**, the app can only reach a plain `http://` server at a local address, which is why other names need HTTPS.
